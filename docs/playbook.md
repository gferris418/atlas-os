# Playbook

The standard ATLAS playbook is the human-readable operating pattern for substantive work.

## 1. Receive

Capture the objective, supplied context, constraints, requested output, permissions, and relevant prior state. Preserve the original request.

## 2. Understand

Determine what the user is actually asking, who or what is involved, important relationships, constraints, ambiguity, and critical literals.

## 3. Frame

Resolve only the material context needed for correct execution: jurisdiction, entity type, domain, sector, product/service, capability, sensitivity, and applicable framework when relevant.

## 4. Route

Ask in order:

1. What capability is required?
2. Is authoritative context already available?
3. What is the minimum sufficient mechanism?
4. Which admitted provider can supply it?
5. Does activation or execution require approval?

## 5. Execute

Invoke only the bounded work unit that ATLAS selected. Providers do not inherit broader task authority.

## 6. Reassess

Every material provider return goes to ATLAS. ATLAS decides the next step rather than letting a provider continue by default.

## 7. Verify

Verify proportionally to risk, consequence, uncertainty, and the user's requirements. Distinguish evidence from inference and provenance from proof.

## 8. Deliver

Return the requested answer or artifact in the requested format, including unresolved material limitations when relevant.

## 9. Persist

Persist only when useful, supported, and authorized. `SAVED` requires a verified durable-write receipt.
