# ATLAS OS

ATLAS-OS is a portable operating framework for AI work. When ATLAS is active, every user prompt enters Mission Control first. ATLAS then preserves user authority, applies the three-step preprocessing flow, assigns the required Q0-Q5 quality tier during Minimal Domain Framing, chooses the next execution mechanism, reconciles every provider return, applies the Quality Gate, governs persistence and classification reference data, and verifies outcomes before delivery.

**Version:** `3.0.3`

## Operating invariant

> **Mission Control is the first ATLAS governance gate. ATLAS governs. Providers execute bounded capabilities. Every provider returns to ATLAS. The user retains authority over consequential actions. Quality and decision utility come before performance.**

Mission Control precedes preprocessing and is not a fourth preprocessing step. The preprocessing sequence remains exactly: **Understand + Normalize → Minimal Domain Framing → Route**.

ATLAS 3.0.3 uses Q0-Q5 assurance tiers and a mandatory Quality Gate before authoritative delivery. Performance improvements such as verified-state reuse, delta refresh, caching, indexing, duplicate elimination, and parallel independent retrieval operate inside the required quality tier and may not weaken evidence, verification, provenance, governance, approvals, or material uncertainty disclosure.

`FAST_TEXT` is the default compact presentation mode for ordinary text surfaces; presentation never changes research depth. Completed-turn persistence uses immutable user-visible prompt/response events only when an authorized durable-write capability is actually available. Hidden chain-of-thought, system/developer instructions, secrets, signed URLs, and raw secret-bearing tool payloads are excluded.

Host skill loading remains capability- and relevance-dependent. ATLAS-OS guarantees Mission Control-first behavior while ATLAS is active; it does not claim universal prompt injection or background persistence on hosts that have not exposed those capabilities.
