# ATLAS OS 2.0.2-rc.6

**Control revision:** `atlas-bootstrap-2026-10-22-r10`  
**Status:** Candidate; external verification pending  
**Target stable:** `2.0.2`

## Purpose

`2.0.2-rc.6` adds the canonical ATLAS capability layer without changing the fundamental architecture introduced by the rc.5 Collection-Need/ARGUS boundary.

ATLAS remains the fixed operating architecture. ARGUS remains a governed specialist subsystem for structured intelligence collection. Capability planning consumes the existing Collection-Need decision and cannot self-activate ARGUS.

## Canonical capabilities

The candidate defines ten provider-neutral capabilities:

1. `atlas.deep-research`
2. `atlas.evidence-governance`
3. `argus.collection`
4. `atlas.procurement-intelligence`
5. `atlas.execution-governance`
6. `atlas.agent-security`
7. `atlas.commercial-contract-review`
8. `atlas.corporate-finance`
9. `atlas.economic-policy-intelligence`
10. `atlas.classification-crosswalk`

Evidence Governance, Execution Governance, Agent Security and Classification Crosswalk are kernel services. Procurement Intelligence is hybrid. ARGUS Collection is specialist. The remaining capabilities are routed ATLAS reasoning capabilities.

## Runtime changes

- Adds deterministic canonical capability planning after request triage/Collection-Need interpretation.
- Projects the capability plan into `ExecutionResult` and live Dashboard state.
- Adds `CAPABILITY_PLANNING` to the visible execution trace.
- Preserves `collection_mode` as the only authoritative ARGUS activation decision.
- Pins ARGUS `2.2.0-rc.2` at merged commit `be5fcaf48d84e14e147288e05f3fe90bc96744ac`.
- ARGUS rc.2 uses bounded PIR/EEI collection tradecraft internally; ATLAS retains Evidence Governance, analysis and decisions.

## Governance contracts
