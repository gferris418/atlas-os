# ATLAS OS v2.0.1 Release Decision

**Date:** 2026-10-20  
**Channel:** stable  
**Status:** RELEASED  
**Predecessor:** 2.0.1-rc.1 at `53ae8723fe2939898015810a821f61a93ed8b9c8`

## Verification basis

ATLAS `2.0.1-rc.1` passed the dependency audit, unit, conformance, regression, integration, and repository-validation gates before and after merge. The candidate introduced execution leases, lifecycle-aware signing trust, and Domain Context Handoff `1.2.0` without creating a second execution spine or changing ARGUS authority boundaries.

The downstream ARGUS candidate pinned the immutable ATLAS hardening commit, passed its full contract suite, and subsequently passed credentialed cross-repository E2E in both `main`-push and same-repository pull-request contexts. Before stable promotion, enforceable `main` branch protection was enabled and independently read back on both repositories.

The stable promotion changes release/version metadata, the version-bound contract test and ChatGPT compatibility identity, changelog/current-release documentation, and this release decision. It does not change ATLAS runtime logic or schema semantics from the validated `2.0.1-rc.1` candidate.

## Residual verification

The following post-GA controls remain open and must not be represented as completed:

- `MIG-029` — independent New Chat and ChatGPT Work bootstrap proof;
- `MIG-037` — independent latest-control propagation across supported surfaces;
- `DTIF-RECONCILIATION` — reconciliation requiring authoritative DTIF source data not present in the bootstrap repository.

They are non-release-blocking under the existing operator decision and remain governed migration work.

## ARGUS compatibility and sequencing

ARGUS stable promotion is sequenced after this ATLAS release-state merge. ARGUS must repin its compatibility descriptor, workflow checkout, product metadata, runtime wire-version assertions, and tests to the exact merged ATLAS v2.0.1 commit, then pass both its protected `contract-tests` gate and the credentialed cross-repository E2E gate before ARGUS receives its own `v2.0.1` stable tag.

## Publication gate

After this release state is merged to protected `main`, tag `v2.0.1` on that exact merged commit. The tag-triggered release workflow must rerun dependency audit, all ATLAS test suites, repository validation, deterministic packaging, and tag/manifest consistency before GitHub release publication.
