# ATLAS-OS

Use this skill when the user asks to run, install, apply, or govern work with ATLAS-OS, or when a task explicitly requires the ATLAS execution spine.

1. Locate the repository root, read `atlas-ai.yaml`, then `atlas-os.yaml` as product/release authority.
2. Preserve untouched input and interpret task intent plus target objects.
3. Apply the Collection-Need Gate independently of task intent: `NONE`, `ATLAS_DIRECT`, `ARGUS_COLLECTION`, `HYBRID`.
4. Keep ordinary factual/policy/rules research and ordinary task execution in ATLAS. Policy subject matter alone is not an ARGUS trigger.
5. Route `intelligence_collection` to ARGUS only for `ARGUS_COLLECTION` or `HYBRID`: named target profiling/dossiers, buyer-product requirements, procurement plans/pipelines, opportunity discovery, supplier/competitor/stakeholder landscapes, installed-base collection, market mapping, or monitoring.
6. In `HYBRID`, ARGUS collects and packages evidence; ATLAS retains strategic analysis, forecasting/scenarios, opportunity qualification and decisions.
7. Resolve material Domain Context Services through ATLAS: terminology, taxonomy, economic sector, industry/activity, product/service, procurement, customs/trade, capability, ontology, laws, standards, frameworks and benchmarks. ARGUS may suggest mappings but cannot silently replace ATLAS canonical classification.
8. Read only the active machine contracts, registries, migration controls and host guidance material to the task. `spec/domain-intelligence.yaml` is a deprecated compatibility alias, not active machine authority.
9. Treat Mission Control as human command/intervention; Control Plane as authoritative governance; Observability as read-oriented measurement; Dashboard as read-only projection. Dashboard state changes become Mission Control commands.
10. Establish a plan ID, routing preview, approval gates and minimum admitted provider set before execution. Execute one authorized atomic work unit at a time.
11. Preserve evidence, authorization, verification, persistence and delivery controls. Never present ATLAS as a device/desktop OS.
12. Use host slug `hermes-agent` in Hermes and the host's validated slug elsewhere. The Python runtime is a reference implementation, not a second authority.
13. Before completion, verify the requested outcome with fresh evidence. Report unavailable or blocked capabilities explicitly.
14. Governing identity is `2.0.2-rc.5` / `atlas-bootstrap-2026-10-22-r9`.

## Boundaries

- Never weaken host permissions or ATLAS approvals.
- Never treat model output as verified evidence by itself.
- Never report durable state as saved without an authorized write and verified receipt.
- Never create provider-specific core semantics.
- Never activate ARGUS merely because a topic sounds analytical; activation depends on structured collection need.
- Never let ARGUS make the final ATLAS business decision or create a competing execution spine.
- Never close an external-proof migration from repository-local or self-generated evidence.
